# Cover Composition · 封面该放哪些元素来传达选题

`thumbnail-vs-slide.md` 管的是**易读性**（大字、单焦点、160px 可读）。这份管的是**内容传达** - 同样一张读得清的封面，放对元素能 3 秒说清选题，放错就只是「一句好看的标语」。

> 来源：impeccable 选题实战的多轮用户反馈。手搓封面初版「读得清但传达不到位」，被逐条逼出下面这些硬规则。

## 1. 三信号原则（最高优先）

封面要让人 3 秒读出三件事。**做完封面先自检这三条，缺哪个补哪个**：

| 信号 | 问题 | 手段 |
|---|---|---|
| **是什么** | 这期讲的主角是谁？ | 产品名 / 概念**必须是显眼主元素**，不是角标 |
| **什么品类** | 是 agent skill？CLI？模型？框架？ | 品类标签（`Claude Code · Agent Skill`）+ 类别专属视觉信号 |
| **什么领域** | 设计？安全？数据？运维？ | 领域视觉锚（见下「领域锚」） |

**反例（这次踩的）**：初版把中文标语「祛 AI 味」做成最大字，产品名 impeccable 缩成顶角小字 → 用户：「品牌名不显眼，是不是品牌不是核心？」。其实产品**就是**选题核心。改成产品名为最大主元素后才对。

### 品类信号怎么给
- **agent skill / 命令行工具** → 放**斜杠命令条**（`/polish /bolder /colorize`）或终端提示符 `>`，一眼是「可调用的技能/命令」。比任何文字说明都直接。
- **模型** → 厂商 logo + 参数/版本（见 `brand-logos.md`）。
- **框架 / 库** → 代码片段或 import 行 + star 数。
- **产品 / SaaS** → 产品 logo + 一句价值主张。

### 领域锚（让人看出是哪个领域）
- **设计** → before/after UI 小样、色板 swatch、字体 specimen（`Aa`）。
- **安全** → 终端告警、🔒、CVE/红色高亮、扫描结果。
- **数据 / 分析** → 图表骨架、大数字、网格。
- **基础设施 / 运维** → 架构节点、管线箭头、blueprint 线稿。
- 领域锚常常**和品类信号是同一个元素**（命令条既证明是 skill，命令名又点出领域）。

## 2. before → after 装置（转变类选题通用）

凡是「把 X 变成 Y」「治某病」「优化前/后」「重构」「祛 XX 味」这类**转变型选题**，放一个 before→after 对照小样，是 **领域感 + 价值传达 + 填空白** 三合一的最强单元。

结构（可做成可复用 partial）：
- 两个「设备框」mini（各 ~330px 宽、~360px 高，圆角，像缩小的浏览器/卡片）
- 中间一个 accent 色箭头 `→`
- 每框顶部小标签：左 `✕ 改之前` / 右 `✓ 改之后`
- **before 框**：堆满该领域的「坏味道」典型（设计类 = 紫蓝渐变 + 卡片套卡片 + Inter + 灰字）
- **after 框**：同领域的「好」版本（用本期品牌色/字体渲一个干净样）

这次的实现见 contenthub `videos/20260602-impeccable-design-skill/cover.html` 的 `.demo` 块。

## 3. 砍 chrome / 品牌只出现一次（并入验收）

「简洁」不是留白，是**砍掉次要 chrome，把空间让给有信息量的视觉**。

- **品牌署名全图只出现一次。** 反例（这次踩的）：VerySmallWoods 同时出现在右上角和页脚 → 用户：「冗余」。删到只剩左下一处。
  - 注意区分**产品名**（选题主角，要显眼）和**频道署名**（作者标识，低调一次即可）——这是两个不同的东西，不算重复。
- **默认不放**这些次要 chrome，除非有信息价值：日期、`Ep ·` 胶囊、上下分隔横线、`// 标签` 这类装饰性 label、重复的副标。
- 砍完留出的空间，用 before/after、命令条、大数字这类**有信息量的视觉**填，而不是留一大片黑。

## 验收自检清单（并入 SKILL.md Step 5）

- [ ] **三信号**都到位？（是什么 / 什么品类 / 什么领域 - 逐条指认画面里哪个元素负责）
- [ ] 主角（产品/概念）是不是**最显眼的主元素**？
- [ ] **品牌署名是否只出现一次**？产品名 vs 频道署名有没有混淆或重复？
- [ ] 有没有可删的**次要 chrome**（日期/胶囊/横线/装饰标签）？
- [ ] 空白处是**有意义视觉**还是纯空？转变类选题有没有上 before/after？
- [ ] 3 秒原则 / 160px 可读（见 `thumbnail-vs-slide.md`）。

## 多方向预览工作法（推荐）

定稿前，**一次出 3-4 个差异化方向让用户挑**（不同风格 / 配色），而不是单版反复改 - 收敛更快，也更容易撞出对的方向。这次出了 A 杂志浅色 / B 粗野 / C 暖色块 / D 瑞士蓝 四版预览，用户一眼选定方向后再精修。各方向存档在 `cover-styles/`，命名 `{字母}-{风格}.html/.png`。
